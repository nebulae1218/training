需求文档 / 02 业务流程与实体关系

业务流程与实体关系

帮助研发理解业务如何流转、数据如何关联，以及任务、组织、资源三类规则如何在系统内落地。

2.1 核心业务流程图

2.1.1 端到端主流程

客户管理后台主机厂 / 集团 / 门店管理员操作

发布与授权资源授权、组织下发、岗位匹配
↓
三条并行使用路径

  1. 系统由客户管理后台完成内容资源的创建、配置、发布和任务下发；由学员端完成课程学习、AI模拟陪练和正式考核。
  2. 独立学习、自由陪练、管理员下发任务是并行使用路径，不是所有行为都必须先创建任务。
  3. 主流程的数据流转为：内容资源 → 任务/授权 → 学员执行 → 训练记录与能力分析。

2.1.2 客户管理后台主流程

维护组织与账号确定谁能管理、谁能学习
→
准备内容资源知识库、课程、剧本、模拟客户、考核、话术库、词库
→
配置任务或授权选择组织、岗位、人员和内容
→
发布使用生成任务待办或开放可用资源
  1. 管理员既可以直接发布资源授权，也可以组合成任务后下发。
  2. 任务发布后，系统生成学员待办；资源授权后，学员可自主进入学习或陪练。
  3. 主机厂可跨集团下发，集团可向下属门店下发，门店可面向本店学员下发。

2.1.3 学员端执行流程

↓

↓

  1. 一次陪练只使用一个剧本；一次AI实训考核也只使用一个指定剧本。
  2. 正式考核只展示标题、简介等基础信息，不向学员公开完整剧本内容、客户画像和评分细则。
  3. 每次陪练和每次考核结束后，系统都生成对应的记录和能力诊断。

2.1.4 培训任务固定流程

课程学习完成全部必修课程
→
AI陪练完成任务指定剧本的陪练要求
→
正式考核参加考试并达到合格线
→
任务完成
  1. 培训任务的顺序固定为：课程 → 陪练 → 考核，前一阶段完成后才能解锁下一阶段。
  2. 学习任务、陪练任务、考试任务可独立存在，不依赖培训任务。
  3. 陪练任务完成陪练即可；考试任务以正式考试合格为完成条件。

2.2 实体关系图（ER）

2.2.1 核心实体分组

1. 组织与人员

组织、门店、学员、角色/岗位，用于确定资源范围、任务接收对象和数据权限。

2. 内容资源

知识库、课程、剧本、模拟客户、考核、话术库、词库，用于支撑学习、陪练和考试。

3. 业务编排

任务是核心编排对象，用于将课程、剧本和考核下发给组织、岗位或人员。

4. 执行结果

学习记录、训练记录、考试记录、能力诊断、统计报表，用于分析培训效果。

  1. 知识库、词库、话术库属于基础资源，不直接下发给学员执行，但会被课程、剧本、考核引用。

2.2.3 业务对象关联规则

  1. 一个课程可引用多个知识库；一个剧本可引用多个知识库、多个词库规则和多个模拟客户。
  2. 一个剧本可适用于多个岗位；一个学员也可拥有多个岗位。
  3. 一个任务可关联多个课程、多个剧本或一个考核；但学员每次启动陪练或AI实训时，只会执行其中一个具体剧本。
  4. 一份任务可以关联多个集团、门店或岗位；一名学员命中多个条件时，系统需要按任务去重。

2.2.4 任务核心业务模型

1. 场景

主机厂、集团或门店，需要把课程、陪练、考试以任务的方式下发给目标学员。

2. 谁创建

具备任务管理权限的管理员，在客户管理后台创建任务。

3. 发给谁

可按组织、门店、岗位或指定学员下发；一份任务可关联多家门店。

4. 包含什么

任务可包含课程、剧本和考核，并配置开始时间、截止时间和完成条件。

5. 学员如何执行

学员在学员端接收任务后，按任务类型完成学习、陪练或考试。

6. 产出什么

输出任务进度、学习记录、训练记录、考试成绩和能力分析，用于统计和复盘。

  1. 示例：主机厂向100家门店下发培训任务时，业务上是一份任务关联100家门店，不是创建100份独立任务。
  2. 集团管理员可以查看本集团下属门店的任务执行情况；主机厂可以跨集团查看总体执行情况。
  3. 本节用于帮助产品和研发理解任务在业务上的作用，不是数据库设计说明。

2.2.5 辅助对象说明（供研发设计时考虑）

对象为什么需要对需求表达的帮助
资源版本课程、剧本更新后，历史记录仍需知道当时用的是哪个版本保证训练结果和考试结果可追溯
任务接收快照组织、岗位、人员会变化，系统需保留任务发布当时的接收范围保证任务统计口径稳定
评分明细不仅要有总分，还要知道各维度为何得分、失分支撑能力诊断、问题定位和报表展示
考试尝试记录学员可能多次考试或补考支撑重考规则和成绩追踪
  1. 这些对象不是单独给用户操作的“主功能页面”，而是研发在设计数据结构和统计逻辑时需要考虑的支撑对象。
  2. 在需求文档中保留这部分，是为了避免后续出现“页面做出来了，但历史追溯、统计和补考无法落地”的问题。

2.3 任务状态与流转规则

  1. 任务管理状态用于描述一份任务本身是否已发布、是否可执行。
  2. 学员执行状态用于描述每位学员在该任务中的实际进度和结果。
  3. 二者必须分开存储和统计：一份任务可以处于“进行中”，但不同学员可能分别处于“未开始、进行中、已完成、未通过”等不同状态。

2.3.1 任务管理状态机

状态机：任务层

→
已发布
→
进行中
→
已结束
已取消可由已发布 / 进行中转入
  1. 草稿：任务已创建但尚未下发。
  2. 已发布：任务已发布，等待到达生效时间或开始被学员执行。
  3. 进行中：任务已进入执行期，学员可以学习、陪练或考试。
  4. 已结束 / 已取消：任务不再新增执行，但仍可查看历史数据。

2.3.5 异常场景处理

异常场景需求处理口径

考试中断记录异常，按考试规则决定是否允许继续或重考

超过截止时间保留逾期标记；是否允许继续执行由任务规则决定

  1. 主机厂可以跨多个经销商集团查看培训执行情况。
  2. 集团管理员可以查看本集团下属各门店全部学员的训练记录和考试结果。
  3. 门店管理员管理本店学员；学员仅查看自己的任务、记录和能力诊断。
  4. 学员是最末级统计对象，且需要结合岗位一起分析。

2.4.2 权限分类

1. 功能权限

控制是否可访问课程管理、剧本管理、任务管理、训练记录与能力分析等页面，以及新增、编辑、发布等操作。

2. 数据权限

控制能看到哪些集团、门店、学员及其训练、考试、任务数据。

3. 资源权限

控制知识库、课程、剧本、考核、话术库、词库等资源的查看、引用和维护权限。

4. 任务权限

控制任务创建、下发、查看和统计能力。本系统不设置审批权限。

2.4.3 核心资源继承规则

资源类型上级组织能力下级组织能力
主机厂预设剧本创建、编辑、发布、授权在授权范围内查看和引用；不可修改，不提供复制功能
主机厂课程 / 考核创建、发布、授权在授权范围内查看、学习、引用到任务中
集团自建资源集团维护并向门店授权在授权范围内查看或使用
